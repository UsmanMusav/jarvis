# Задание для агента: опубликовать проект на GitHub

Этот файл — инструкция для ИИ-агента с подключённым коннектором GitHub.
Человек-пользователь передаёт готовый проект и просит создать репозиторий и выложить код.

---

## 1. Что передаётся

**J.A.R.V.I.S.** — настольный голосовой помощник на Python (Windows / macOS / Linux).
Слушает микрофон, выполняет команды на компьютере, отвечает на вопросы, говорит
заранее озвученными репликами. Есть установщики и автообновление через GitHub Releases.

Состояние: **код готов и протестирован**, 82 автотеста проходят, интерфейс проверен
на реальном дисплее. Не сделан ровно один шаг — проект ещё нигде не опубликован.

| | |
|---|---|
| Язык | Python 3.10+, интерфейс на tkinter |
| Версия | `1.1.0` (единственный источник правды — `core/version.py`) |
| Файлов | 72, около 9 МБ (из них ~7 МБ — звук и иконки) |
| Внешние зависимости в рантайме | все опциональные, приложение запускается и без них |

## 2. Что нужно сделать

### Шаг 0. Уточнить у пользователя

Спросите (одним вопросом, с вариантами), если он сам не указал:

1. **Имя репозитория** — по умолчанию предложите `jarvis-voice-assistant`.
2. **Лицензия** — в проекте её нет. Предложите MIT (обычный выбор для такого проекта)
   либо «не добавлять».

Видимость **не спрашивайте**, см. ниже — она предопределена технически.

### Шаг 1. Создать ПУБЛИЧНЫЙ пустой репозиторий

> **Это не вопрос вкуса, а техническое требование.** Автообновление в
> `core/updater.py` ходит в `https://api.github.com/repos/<repo>/releases/latest`
> **без токена**. Для приватного репозитория GitHub отвечает `404`, и обновления
> молча перестанут работать. Если пользователь всё же хочет приватный — предупредите,
> что автообновление придётся отключить (`update_repo: ""`) или дорабатывать под токен.

Параметры при создании:

| Поле | Значение |
|---|---|
| Название | то, что выбрал пользователь (по умолчанию `jarvis-voice-assistant`) |
| Описание | `Голосовой помощник для компьютера в стиле Джарвиса: распознавание речи, управление ПК, установщики и автообновление` |
| Видимость | **public** |
| Инициализация | **пустой**: без README, без .gitignore, без лицензии — они уже в проекте и при `git push` дадут конфликт |
| Topics (если коннектор умеет) | `voice-assistant`, `jarvis`, `python`, `speech-recognition`, `tkinter`, `desktop-app`, `russian` |

### Шаг 2. Подставить адрес репозитория в код — ДО коммита

В трёх файлах стоит заглушка. Есть готовый скрипт:

```bash
python tools/_patch_repo.py ВЛАДЕЛЕЦ/РЕПОЗИТОРИЙ
```

Он правит:

| Файл | Что меняется | Зачем |
|---|---|---|
| `core/config.py` | `"update_repo": ""` → `"ВЛАДЕЛЕЦ/РЕПОЗИТОРИЙ"` | автообновление заработает сразу после установки, без ручной настройки |
| `build/installer.iss` | `#define AppURL` | ссылки «Поддержка» и «Обновления» в установщике Windows |
| `README.md` | все упоминания `username/jarvis` и `ваш-логин/jarvis` | документация |

Скрипт идемпотентен и проверен: повторный запуск пишет «нечего менять».
Если инструмента запуска кода нет — отредактируйте эти три места вручную.

### Шаг 3. Залить файлы

**Вариант А — git (предпочтительно).** Один коммит, бинарники без возни:

```bash
python tools/_patch_repo.py ВЛАДЕЛЕЦ/РЕПОЗИТОРИЙ
git init
git add -A
git commit -m "J.A.R.V.I.S. 1.1.0 — голосовой помощник с установщиком и автообновлением"
git branch -M main
git remote add origin https://github.com/ВЛАДЕЛЕЦ/РЕПОЗИТОРИЙ.git
git push -u origin main
```

**Вариант Б — через API коннектора (создание файлов по одному).**
Тогда учтите две вещи:

* В проекте **25 бинарных файлов `.wav`** (`assets/voice_ru/`, `assets/voice_en/`) и
  **13 изображений** (`assets/icons/` — 10, `assets/icon.png`, `docs/*.png` — 2).
  Их нельзя отправлять как текст — только base64 через Contents API.
  Если потерять звук, приложение не сломается (есть запасной синтез речи),
  но пропадёт весь смысл «голоса Джарвиса». Проверьте, что они долетели.
* `.gitignore` при таком способе не применяется автоматически — **не загружайте**
  `config.json`, `notes.txt`, `__pycache__/`, `dist/`, `.venv*/`.

### Шаг 4. Выпустить релиз

```bash
git tag v1.1.0
git push origin v1.1.0
```

Тег вида `v*` запускает `.github/workflows/release.yml`. Он на трёх ОС:
прогоняет тесты → собирает установщики → считает SHA256 → публикует релиз.

Если коннектор не умеет пушить теги — создайте релиз с тегом `v1.1.0`
через API релизов, workflow всё равно сработает по событию `push` тега.

### Шаг 5. Проверить и отчитаться

- [ ] Репозиторий публичный, файлов около 72
- [ ] Звук на месте: `assets/voice_ru/` — 13 файлов, `assets/voice_en/` — 12
- [ ] `config.json` и `notes.txt` **не** попали в репозиторий
- [ ] `core/config.py` содержит реальный `update_repo`, а не пустую строку
- [ ] Вкладка **Actions**: `Тесты` зелёные
- [ ] Вкладка **Actions**: `Сборка и публикация релиза` отработала (10–15 минут)
- [ ] В `/releases/latest` появились 5 файлов:
      `JARVIS-Setup-1.1.0.exe`, `JARVIS-1.1.0-windows-portable.zip`,
      `JARVIS-1.1.0-macos.dmg`, `JARVIS-1.1.0-linux-x86_64.tar.gz`, `SHA256SUMS.txt`

Пользователю верните: **ссылку на репозиторий** и **ссылку на релиз**.

## 3. Чего делать не нужно

* Не переписывайте код — он рабочий и покрыт тестами.
* Не трогайте `.github/workflows/*` — там уже проставлены нужные
  `permissions: contents: write`.
* Не коммитьте `config.json` (создаётся при первом запуске, содержит
  пользовательские настройки) и `notes.txt`.
* Не меняйте `AppId` в `build/installer.iss` — этот GUID связывает версии между
  собой, при его смене обновление поставится рядом со старым, а не поверх.

## 4. Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| `git push` отклонён, «fetch first» | Репозиторий создан с README. Либо пересоздайте пустым, либо `git pull --rebase origin main` и снова push |
| Workflow не запустился | Тег не формата `v*`, либо в настройках репозитория выключены Actions |
| Сборка упала на Windows | Чаще всего Inno Setup. В workflow он ставится через `choco install innosetup`; портативный zip соберётся в любом случае |
| Сборка упала на Linux | Нужны системные пакеты, они уже прописаны в workflow: `python3-tk`, `portaudio19-dev`, `libasound2-dev`, `espeak-ng` |
| Релиз создан, но пустой | Проверьте шаг `Выложить артефакты`: у него стоит `if-no-files-found: error`, значит сборка не дала файлов |

```

│   ├── version.py             ВЕРСИЯ — правится при каждом релизе
│   ├── config.py              настройки, пути (у собранной версии — в папке данных ОС)
│   ├── ui.py                  интерфейс HUD на tkinter + окно настроек + баннер обновления
│   ├── assistant.py           слово-активатор, выбор языка, маршрутизация, подтверждения
│   ├── speech.py              распознавание речи: Google Web Speech или Vosk (оффлайн)

│   ├── commands.py            действия на ПК, три ветки под Windows/macOS/Linux
│   ├── brain.py               ответы: время, погода, математика, Википедия, статус системы
│   └── updater.py             автообновление через GitHub Releases
├── assets/
│   ├── voices.json            карта «ключ → фраза»; нет файла — скажет синтезатор

│   ├── voice_en/ (12 wav)
│   └── icons/                 .ico, .icns, PNG 16…1024
├── build/
│   ├── jarvis.spec            PyInstaller
│   ├── installer.iss          Inno Setup; установка без прав администратора
│   └── build_windows.bat · build_macos.sh · build_linux.sh

│   ├── _patch_repo.py         ← подстановка адреса репозитория (нужен на шаге 2)
│   ├── setup_github.sh/.bat   то же + git push + тег, для запуска человеком
│   ├── split_clips.py         нарезка длинной озвучки на фразы по паузам
│   └── polish_clips.py        затухание и паддинг клипов
├── tests/                     82 проверки, сеть не нужна, действия заглушены

│   └── test_updater.py        23 — версии и выбор файла под ОС
```

Запуск тестов локально (сеть и зависимости не нужны):

```bash
python tests/test_commands.py && python tests/test_assistant.py && python tests/test_updater.py
```

## 6. Что осталось нереализованным

Если пользователь захочет продолжить — вот честный список:

* **Подпись кода отсутствует.** Windows SmartScreen покажет «неизвестный издатель»,
  macOS потребует «правый клик → Открыть». Лечится платным сертификатом
  и нотаризацией у Apple.
* **Голос не является озвучкой из фильма.** Это подобранные по тембру голоса
  (спокойный британский для английского, низкий «дворецкий» для русского).
  Воспроизвести голос Пола Беттани или Вячеслава Баранова нельзя — это
  клонирование голоса конкретного актёра.
* **Нет английского клипа `updated.wav`** — эта фраза произносится синтезатором.
* **Ответы на вопросы — без нейросети**: время, погода, калькулятор, Википедия,
  статус системы, заготовленные реплики. Подключение ИИ по API-ключу не делалось.
* **Сборки только x86_64.** Для Apple Silicon и ARM-Linux нужны отдельные
  задания в матрице workflow (сам выбор файла под ARM в обновляторе уже написан и протестирован).
* Не сделано: сворачивание в трей, глобальная горячая клавиша, автозапуск на macOS/Linux
  (в установщике Windows автозапуск есть, галочкой).
